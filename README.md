# 권역별 운영 실험 보드

대화역과 킨텍스 권역에서 반복되는 배달 문제를 운영 담당자가 직접 검증하도록 돕는 작은 현장 운영 도구입니다.

이 프로젝트는 배달 지연률을 예측하는 모델이 아닙니다. 공개 교통 데이터와 음식점 위치를 먼저 확인하고, 주문 집중, 이동 병목, 매장 조리 적체라는 원인 가설을 비교한 뒤 조치 전후의 지연시간과 실행 비용을 기록합니다.

## 문제 정의

특정 권역의 배달이 늦어져도 주문량, 도로 이동, 매장 조리 중 어느 단계가 실제 병목인지 평균 지표만으로는 구분하기 어렵습니다. 원인을 잘못 짚으면 효과 없는 조치와 추가 비용이 반복됩니다.

이 보드는 다음 판단 흐름을 한 화면에 남깁니다.

```text
이상 신호 확인
  → 원인 가설 3개 비교
  → 공개 API와 현장 확인으로 반증
  → 실행안과 관계자 제약 기록
  → 조치 전후 효과와 비용 비교
  → 유지, 수정, 중단 결정
```

## 화면에서 할 수 있는 일

- 대화역과 킨텍스 주변 교통 구간의 속도, 지체시간과 혼잡 등급 확인
- 대화역, 킨텍스와 주요 이동축을 지도에서 확인
- 교통 API 조회 결과를 브라우저에 누적 저장
- Open-Meteo에서 현재 기온, 강수량과 풍속 확인
- 킨텍스 주변 음식점 검색 API 상태 확인
- 원인 가설의 우선순위 변경 및 반대 증거 기록
- 관찰 사실, 관계자 제약과 선택한 조치 기록
- 조치 전후 지연시간과 실행 비용으로 변화율 계산
- 사건 기록을 브라우저에 저장하고 CSV로 내보내기
- 조치 전후 내용을 인쇄 가능한 실험 리포트로 출력
- 누적 교통 데이터를 Tableau용 CSV로 내보내기

## 데이터 경계

| 구분 | 사용 자료 | 화면 표시 방식 |
| --- | --- | --- |
| 실제 공개 데이터 | 경기도 교통정보센터 구간 소통 API | 실제값 |
| 실제 공개 데이터 | 카카오 장소 검색 API | 음식점 위치와 검색 결과 |
| 연결 준비 상태 | 카카오 앱의 지도 및 로컬 서비스 | 서비스가 비활성화되면 확인 필요 |
| 공개되지 않은 내부 자료 | 주문 수, 라이더 수, 조리 완료 시간 | 가상 운영 데이터 |
| 운영자가 입력하는 자료 | 현장 관찰, 제약, 조치 전후 값과 비용 | 사건 기록 |

주문 수나 라이더 공급을 실제 배민 내부 데이터처럼 표현하지 않습니다.

## 실행 방법

필요 조건은 Node.js 18 이상입니다.

### 1. 환경변수 파일 만들기

Windows PowerShell에서 저장소 폴더 안에 입력합니다.

```powershell
Copy-Item .env.example .env
```

`.env`에 발급받은 키를 입력합니다.

```env
GYEONGGI_TRAFFIC_API_KEY=발급받은_경기도_교통_API_키
KAKAO_REST_API_KEY=발급받은_카카오_REST_API_키
```

`.env`는 `.gitignore`에 등록되어 있어 저장소에 올리지 않습니다.

### 2. 서버 실행

```powershell
node server.mjs
```

브라우저에서 [http://localhost:4173/](http://localhost:4173/)을 엽니다.

### 3. API 확인

- 화면의 `교통 API 확인` 버튼으로 대화역과 킨텍스 주변 구간을 조회합니다.
- 화면의 `장소 API 확인` 버튼으로 킨텍스 주변 음식점 검색을 확인합니다.
- 화면의 `날씨 API 확인` 버튼으로 현재 기상 신호를 확인합니다. Open-Meteo는 별도 키가 필요하지 않습니다.
- 카카오 API가 오류를 반환하면 카카오 개발자 콘솔에서 앱의 지도 및 로컬 서비스 활성화 여부를 확인합니다.

## Tableau로 이어지는 흐름

1. 교통 API를 여러 번 조회해 이력을 쌓습니다.
2. `태블로용 누적 CSV`를 내려받습니다.
3. 화면의 `태블로 열기`를 누릅니다.
4. Tableau에서 `regional-ops-traffic-history.csv`를 연결합니다.

현재 버튼은 Tableau Public 탐색 화면으로 연결됩니다. 게시된 워크북 주소가 생기면 링크를 교체할 수 있습니다.

## 개발 중 확인한 범위

2026년 10월 14일 로컬 서버에서 경기도 교통 API를 호출해 대화역과 킨텍스 주변 20개 구간 응답을 확인했습니다. 당시 응답의 평균 속도는 27km/h, 평균 지체시간은 0초였습니다. 이 값은 특정 시점의 API 응답이며 권역의 일반적인 성과나 배달 지연률을 의미하지 않습니다.

코드 문법 검사는 다음 명령으로 확인할 수 있습니다.

```powershell
node --check app.js
node --check server.mjs
```

## 한계와 다음 단계

- 공개 API만으로 배민의 실제 주문 지연률, 라이더 공급, 조리 대기시간을 계산할 수 없습니다.
- 현장 입력값은 운영자가 확인한 사실과 가상 시나리오를 구분해 기록해야 합니다.
- 다음 단계는 카카오 장소 검색 활성화, 현장 관찰 양식 표준화, 여러 날짜의 CSV 누적 비교입니다.

## 개인정보와 키 관리

개인 주소, 연락처와 차량번호를 기록하지 않습니다. API 키는 `.env`에만 보관하며 GitHub에 올리지 않습니다.
